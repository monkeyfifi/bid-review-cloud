# bid-review-cloud — 投标文件审核

## 这是什么

你被赋予了一个投标文件审核任务。本文件夹包含了完成审核所需的全部工具、判词库、流程指引和报告模板。

你的工作流程如下，请严格按步骤执行。

---

## 文件结构

```
bid-review-cloud/
├── README.md              ← 本文件：完整工作流 + 判词库 + 评分模型
├── data/
│   └── keywords.json      ← 678条判决词（废标信号扫描用）
├── scripts/
│   ├── extract_text.py    ← PDF/DOCX文本提取
│   ├── scan_keywords.py   ← 废标信号扫描
│   ├── checker.py         ← 暗标格式检查（技术标DOCX用）
│   └── requirements.txt   ← pip依赖
├── templates/
│   └── 审核报告模板.md     ← 标准报告模板
└── references/
    └── 专家判词库.md       ← 15项废标清单 + 商务清单 + 评分公式
```

---

## 第一步：取数（提取文本）

首先从PDF中提取带行号的文本，作为后续分析的依据。

```bash
pip install -r scripts/requirements.txt
python scripts/extract_text.py "招标文件.pdf" --outdir .
python scripts/extract_text.py "投标文件.pdf" --outdir .
```

产出：`招标文件.lines.txt`、`投标文件.lines.txt`

## 第二步：撒网（扫描废标信号）

用判决词库扫描招标文件，标出关键条款位置。

```bash
python scripts/scan_keywords.py 招标文件.lines.txt --keywords data/keywords.json
```

产出：`招标文件.hits.json`

## 第三步：通读招标文件

阅读 `招标文件.lines.txt`，逐项提取以下信息：

1. **项目基本信息**：名称、编号、采购人、预算金额
2. **废标情形**（重点看"无效投标"条款）
3. **加★实质性条款**（不响应则废标）
4. **资格要求**（营业执照、许可证、财务、税收、社保、无违法记录）
5. **技术参数要求**（带宽、光纤对数、丢包率、时延、IP地址等）
6. **商务条款**（实施时间、付款方式、质保期、响应时间等）
7. **暗标格式要求**（A4纸张、宋体四号、页边距、行距、不得出现身份信息等）
8. **评分标准**（各项分值分配）

## 第四步：通读投标文件 — 逐项比对

阅读 `投标文件.lines.txt`，按以下三维度逐条检查：

### A. 废标项核查（15项）

逐条核对以下废标情形：

| 序号 | 废标情形 | 判定标准 |
|------|---------|---------|
| 1 | 报价超过预算 | 开标一览表报价 > 预算金额 → ❌ |
| 2 | 投标有效期不足 | 投标函天数 < 招标文件要求 → ❌ |
| 3 | 签章不完整 | 缺公章或签字 → ❌ |
| 4 | 资格要求不满足 | 缺扫描件或未盖章 → ❌ |
| 5 | ★条款未明确响应 | 加*项无对应响应 → ❌ |
| 6 | 暗标不合规 | 技术标出现身份信息 → ❌ |
| 7 | 信用记录不良 | 有失信记录 → ❌ |
| 8 | 联合体不合规 | 不允许但联合体投标 → ❌ |
| 9 | 分包不合规 | 不允许但分包 → ❌ |
| 10 | 附加条件 | 含不能接受的附加条件 → ❌ |
| 11 | 未按时提交 | 未按时上传 → ❌ |
| 12 | 解密失败 | 自身原因未解密 → ❌ |
| 13 | 报价明显偏低 | 低于其他且无法证明合理 → ❌ |
| 14 | 节能产品未提供 | 强制采购无认证证书 → ❌ |
| 15 | 无实质响应 | 照抄招标文件无技术资料 → ❌ |

每条说明必须包含：招标原文出处 + 投标原文出处 + 具体判定理由。

### B. 商务条款响应（8项）

| 序号 | 条款 | 检查要点 |
|------|------|---------|
| 1 | ★投标报价 | ≤ 预算 |
| 2 | 实施/完工时间 | 符合招标要求 |
| 3 | 项目实施地点 | 采购人指定地点 |
| 4 | ★付款方式 | 符合招标要求 |
| 5 | 项目验收要求 | 交付后由采购人验收 |
| 6 | ★免费质保期 | ≥ 招标要求 |
| 7 | ★故障响应/修复 | 响应及排除时间 ≥ 招标要求 |
| 8 | 同类业绩数量 | 规定时间以来的同类合同 |

标签：✅ 符合 / ⭐ 优于 / ⚠️ 需确认 / ❌ 不合格

### C. 技术参数响应

逐条对比技术指标，每条标注状态并写明依据。

## 第五步：暗标格式检查（如有技术标DOCX）

如果用户提供了技术标DOCX文件，执行：

```bash
python scripts/checker.py "技术标.docx"
```

检查项：纸张A4、黑色图表、宋体四号常规字、无加粗/倾斜/下划线、页边距上2.5cm其余2cm、行距30磅、无目录、无页眉页脚页码、无身份信息。

将检查结果写入报告第四部分。

## 第六步：生成审核报告

按照 `templates/审核报告模板.md` 的六章结构输出MD文件：

1. **项目信息表**
2. **废标项检查**（表格 + 每条写明招标原文和投标原文）
3. **商务条款响应**（表格 + 标注优于项）
4. **技术参数比对**（表格 + 逐条状态）
5. **暗标格式检查**（如有技术标）
6. **评分预估**（报价 + 商务 + 技术 = 总分）
7. **综合结论**（至少200字，含高风险关注点和具体建议）

文件名：`审核报告_YYYYMMDD_v1.0.md`

---

## 评分模型

**报价分（25分）** = (评标基准价 / 投标人报价) × 25  
评标基准价为所有有效投标最低价。

**商务分（20分）**：
- 同类业绩 5分（每份1分，上限5分）
- 售后服务 8分（低于要求一项减4分）
- 商务标响应 7分（缺一项扣2分）

**技术分（55分）**：
- 服务内容及指标 33分（7个子项）
- 校区互联光纤 12分（每减2对扣4分）
- 实施方案 10分（四档：10/7/4/0）

---

## 输出要求

- 每条比对必须写明招标原文和投标原文两端
- 评分写具体数值和计算过程
- 结论至少200字
- 状态标记：✅ pass / ⭐ better / ⚠️ warn / ❌ fail
